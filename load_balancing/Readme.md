#### pembahasan dari langkah yang dilakukan
1. Tahap pertama dalam membangun sistem terdistribusi ini adalah pengembangan aplikasi web sebagai backend service utama. Dalam modul ini, aplikasi dibangun menggunakan framework Blacksheep dengan pola arsitektur MVC (Model-View-Controller) untuk menyediakan endpoint dasar yang siap menerima permintaan . Secara fungsional, aplikasi ini berperan sebagai "pekerja" atau node yang bertugas memproses data dari pengguna, yang nantinya akan diperbanyak jumlahnya untuk menangani beban kerja. Dalam implementasi dunia nyata, langkah ini merepresentasikan pembuatan layanan spesifik atau microservice, seperti layanan login atau keranjang belanja pada aplikasi e-commerce, yang dirancang modular agar dapat dijalankan dan dikembangkan secara independen.

2. Langkah selanjutnya adalah kontainerisasi menggunakan Docker, di mana aplikasi Blacksheep dan Nginx dibungkus beserta seluruh dependency-nya menjadi sebuah image terisolasi melalui Dockerfile . Fungsi utama dari proses ini adalah untuk menjamin konsistensi lingkungan eksekusi, memastikan bahwa aplikasi dapat berjalan dengan perilaku yang sama persis di mana pun ia ditempatkan, baik di laptop pengembang maupun di server produksi. Di industri, praktik ini menjadi standar mutlak (dikenal sebagai Dockerizing) untuk mempermudah pemindahan aplikasi antar-server cloud tanpa khawatir terjadi konflik konfigurasi sistem operasi atau perbedaan versi pustaka perangkat lunak.
   
3. Setelah aplikasi siap, Nginx dikonfigurasi untuk bertindak sebagai Reverse Proxy sekaligus Load Balancer. Melalui penyuntingan file nginx.conf, khususnya pada blok upstream, Nginx mendefinisikan kumpulan server tujuan dan menggunakan perintah proxy_pass untuk meneruskan lalu lintas data yang masuk ke server-server aplikasi tersebut . Fungsinya adalah sebagai pintu gerbang tunggal yang mengamankan server internal dari akses langsung dan membagi beban trafik secara efisien (biasanya dengan metode giliran atau round-robin) agar tidak ada satu server pun yang kelebihan beban. Implementasi nyatanya terlihat pada portal berita atau media sosial besar, di mana pengguna hanya mengakses satu alamat web (domain), namun di belakang layar, load balancer mendistribusikan jutaan permintaan tersebut ke ratusan server yang tersedia di pusat data.

4. Tahap orkestrasi dilakukan menggunakan Docker Compose untuk menjalankan layanan aplikasi dan Nginx secara bersamaan dalam satu jaringan virtual yang terhubung. Fitur paling krusial dalam tahap ini adalah penggunaan perintah scaling (seperti --scale bs_app=2), yang secara instan menduplikasi aplikasi Blacksheep menjadi beberapa instance identik untuk meningkatkan kapasitas layanan . Secara teknis, ini menciptakan redundansi sistem yang diperlukan untuk ketersediaan tinggi (High Availability). Di dunia nyata, konsep ini diadopsi oleh sistem orkestrasi canggih seperti Kubernetes atau fitur Auto Scaling Group di layanan cloud (AWS/Google Cloud), yang memungkinkan sistem menambah jumlah server secara otomatis saat terjadi lonjakan pengunjung yang tiba-tiba, seperti saat momen flash sale atau hari belanja nasional.   

5. Langkah terakhir adalah verifikasi sistem untuk memastikan mekanisme distribusi beban berjalan dengan baik. Melalui pemeriksaan log kontainer secara real-time, dapat diamati bahwa permintaan dari pengguna ditangani secara bergantian oleh instance aplikasi yang berbeda (misalnya log mencatat akses ke app-1 lalu ke app-2) . Hal ini membuktikan fungsi Fault Tolerance (toleransi kesalahan), di mana jika satu instance sedang sibuk memproses data atau mengalami kegagalan (mati), load balancer akan mengalihkan permintaan ke instance lain yang tersedia. Tim operasional IT (DevOps) di perusahaan menggunakan prinsip ini yang dipantau melalui dashboard monitoring untuk menjamin layanan tetap 100% aktif (uptime) dan responsif meskipun terjadi gangguan pada sebagian infrastruktur server mereka.
